ELF Header

这个部分本身不包含具体的代码或数据，而是描述了整个文件的宏观结构和元信息：通过魔数（Magic Number）确认文件格式，并标识是32位还是64位系统；指明文件的数据存储方式（大端序/小端序）和版本信息；提供程序头表（Program Header）和节头表（Section Header）的相对位置索引。

ELF Header在C语言中的标准定义（/usr/include/elf.h）如下，总大小固定为64字节（32位为52字节）。

e_ident[16]：文件指纹与元信息

索引 (Index) 宏定义 含义与常见值
[0-3] ELFMAG0-3 魔数：固定为 0x7F, ‘E’, ‘L’, ‘F’。
[4] EI_CLASS 文件类：1=32位(ELF32)；2=64位(ELF64)。
[5] EI_DATA 数据编码顺序：1=小端序(Little-Endian)；2=大端序(Big-Endian)。
[6] EI_VERSION 版本：通常为 1(EV_CURRENT)。
[7] EI_OSABI 定义该二进制文件所依赖的操作系统与运行时环境。OS ABI：0x00=System V (Unix)；0x03=Linux；0x07=AIX；0x09=FreeBSD；0x0A=NetBSD；0x0B=GNU/Hurd；0x0C=OpenBSD；0x0D=Solaris/Illumos；0x0E=OpenVMS；0x0F=HP NonStop；0x64 - 0xFF=Standalone/Embedded（无操作系统的裸机程序）
[8-15] EI_PAD 填充字节：未使用，通常为 0。

e_type：文件类型

值 (Hex) 宏定义 说明
0x0001 ET_REL 可重定位文件（.o文件），需进一步链接。
0x0002 ET_EXEC 可执行文件（如/bin/ls），有固定的入口地址。
0x0003 ET_DYN 共享目标文件（.so动态库），加载地址可浮动。
0x0004 ET_CORE Core Dump 文件（程序崩溃时生成）。

e_machine：指令集架构

值 (Hex) 宏定义 对应架构
0x3E EM_X86_64 x86-64 架构（Linux 下最常见的 64 位程序）。
0x03 EM_386 x86 架构（32 位 Intel）。
0x28 EM_ARM ARM 架构（常见于嵌入式设备、手机）。
0xB7 EM_AARCH64 AArch64 (ARM 64位)。

e_entry：程序入口地址

对于可执行文件（ET_EXEC/ET_DYN），它存储的是程序第一条指令的虚拟内存地址（Virtual Address, VA）。操作系统加载程序后，会将 程序计数器（Program Counter, PC）跳转到这里开始执行。如果是链接文件（ET_REL），为0。

e_phoff：程序头表的偏移量

Program Header Table在文件中的偏移量，这个表告诉系统如何将文件加载到内存/运行时内存布局，对于可执行文件，值通常不为0。

e_shoff：节头表的偏移量

Section Header Table在文件中的偏移量。这个表描述了文件的节区信息/静态链接信息，主要用于链接和调试。即使这个表被移除，程序通常也能正常运行。

e_flags：处理器标志

这是一个依赖于架构的、与CPU相关的标志字段，用于将CPU信息传递给链接器和加载器。不同架构的取值和含义完全不同，没有统一标准，需要查阅对应架构的手册。

e_ehsize：ELF头大小

ELF Header本身在文件中所占的字节数，如果是32位，固定大小为52字节；如果是64位，固定大小为64字节。

e_phentsize：程序头表中每个条目的大小

对于ELF64，通常是56字节；对于ELF32，通常是32字节。

e_phnum：程序头表中条目的总数量

如果值为0，表示文件没有程序头表（是一个链接文件：xxx.o）；对于可执行文件，值通常≥1。例如，一个简单的“Hello World”程序可能有8-10个段。

e_shentsize：节头表中每个条目的大小

对于ELF64，通常是64字节；对于ELF32，通常是40字节。

e_shnum：节头表中条目的总数量

值可以为0，但通常远大于0。文件中的所有“节”（如 .text， .data， .symtab等）在节头表中都有一个对应的条目。

e_shstrndx：节名字符串表的索引

指向一个特定的节，这个节里面存放的是字符串表存放的是所有节的名称（“.text“， ”.data”， ”.bss”， ”.shstrtab“ 等等）。每个 Section Header中都有一个sh_name字段，存放的就是相对于e_shstrndx所指向的那个节（.shstrtab）的偏移量。从这个偏移处读取，读取节的名称。

Program Header

Program Header是一个结构体，就是ProgramHeaderTable（程序头表）中的条目，用来描述段（Segment）的一些属性，大小由ELF-Header中的e_phentsize字段决定。ProgramHeader在C语言中的标准定义如下（64位和32位都是这么定义的，只是存储位数不同）：

p_type：段类型

下面是一些常见的段类型

类型名称（值） 宏定义 描述
PT_NULL（0） 未使用的段 程序头表中的一个特殊占位符条目，它不代表任何实际的段，而是用于标记程序头表中“空闲”或“保留”的位置。
PT_LOAD (1) 可加载段 操作系统会将其映射到内存，一个可执行文件至少有1个可加载段（通常是两个：代码段+数据段）。
PT_DYNAMIC (2) 动态链接段 包含动态链接信息（.dynamic节）。必须有，否则无法动态链接。
PT_INTERP (3) 解释器段 指定动态链接器路径（如 /lib64/ld-linux-x86-64.so.2）。
PT_NOTE (4) 注释段 供应商或系统特定信息（如ABI版本、构建ID）。
PT_PHDR (6) 程序头表段 程序头表自身所在位置。可选，用于自引用。
PT_TLS (7) TLS段 线程局部存储模板，用于多线程编程。
PT_GNU_STACK (0x6474e551) 扩展 控制栈是否可执行（NX位）。

p_flags：段权限

标识该段在内存中的访问权限，可读/可写/可执行

权限值 宏定义 说明
0x1 PF_X 可执行
0x2 PF_W 可写
0x4 PF_R 可读

内存映射：p_offset、p_vaddr、p_filesz、p_memsz

p_align：对齐要求

表示内存对齐和文件对齐的粒度，必须是2的幂，对齐规则：p_vaddr ≡ p_offset (mod p_align)。

Section Header

节头也是一个结构体，SectionHeaderTable（节头表）中的条目，用来描述节（Section）的一些属性，比如位置、大小、类型、属性等。在C语言中的标准定义如下：

sh_name：节名索引

  1. 指向 .shstrtab节（节名字符串表）的偏移，比如 sh_name = 0x0B，表示在 .shstrtab偏移 0x0B 处查找以 null 结尾的字符串。
  2. 常见节名
    • .text：代码节
    • .data：已初始化数据
    • .bss：未初始化数据
    • .rodata：只读数据
    • .symtab：符号表
    • .strtab：字符串表
    • .shstrtab：节名字符串表
    • .rela.text：重定位表

sh_type：节类型

宏定义（取值） 描述 常见节
SHT_PROGBITS（0x1） SO文件中有实际数据，包含程序的实际内容：代码、数据 .text、.data、.rodata
SHT_SYMTAB（0x2） 符号表 .symtab（完整符号表）
SHT_STRTAB（0x3） 字符串表 .strtab、.shstrtab
SHT_RELA（0x4） 重定位表 .rela.text、.rela.data
SHT_NOBITS（0x8） 不占文件空间，运行时需要分配内存 .bss
SHT_DYNSYM（0x6） 动态链接符号表 .dynsym
SHT_DYNAMIC（0x7） 动态链接信息 .dynamic
SHT_REL（0x9） 旧式重定位 .rel.text（32位用）

sh_flags：节属性标志

标志值 宏定义 描述
0x1 SHF_WRITE 可写（如 .data）
0x2 SHF_ALLOC 运行时需要分配内存
0x4 SHF_EXECINSTR 包含可执行指令（如 .text）
0x10 SHF_MERGE 可合并的重复数据
0x20 SHF_STRINGS 包含以 null 结尾的字符串
0x40 SHF_INFO_LINK sh_info包含节索引
0x0F000000 SHF_MASKOS 操作系统特定标志
0xF0000000 SHF_MASKPROC 处理器特定标志

位置与大小

字段 作用 特殊规则
sh_offset 节在文件中的偏移 必须满足 sh_addralign
sh_size 节的大小（字节） 对于表格类节，是总大小
sh_addr 内存虚拟地址 如果为 0，表示不加载到内存
sh_addralign 对齐要求 必须是 2 的幂，0 或 1 表示无对齐

sh_link和sh_info：链接信息

与sh_type强相关

节类型 sh_link sh_info含义
SHT_SYMTAB SHT_DYNSYM 关联的字符串表节索引 最后一个本地符号索引+1
SHT_REL SHT_RELA 关联的符号表节索引 要重定位的节索引
SHT_HASH 关联的符号表节索引 0
SHT_DYNAMIC 关联的字符串表节索引 0
其他 0 0

sh_entsize：条目大小

对表格类的节表示表格中每个条目的大小，对于非表格节，通常为 0。

节类型 典型 sh_entsize 说明
.symtab 24 (ELF64) 或 16 (ELF32) 符号表条目大小
.dynsym 24 (ELF64) 或 16 (ELF32) 动态符号表条目大小
.rela.text 24 (ELF64) 或 12 (ELF32) 重定位条目大小
.dynamic 16 (ELF64) 或 8 (ELF32) 动态条目大小
.text 0 不是表格，无固定条目大小
.data 0 不是表格，无固定条目大小

常见节

.text

.text 节是保存了程序代码指令的代码节。一段可执行程序，如果存在 Phdr，则 .text 节就会存在于 text 段中。由于 .text 节保存了程序代码，所以节类型为 SHT_PROGBITS 。

.rodata

rodata 节保存了只读的数据，如一行 C 语言代码中的字符串。由于 .rodata 节是只读的，所以只能存在于一个可执行文件的只读段中。因此，只能在 text 段（不是 data 段）中找到 .rodata 节。由于 .rodata 节是只读的，所以节类型为 SHT_PROGBITS 。

.plt

.plt 节也称为过程链接表（Procedure Linkage Table），其包含了动态链接器调用从共享库导入的函数所必需的相关代码。由于 .plt 节保存了代码，所以节类型为 SHT_PROGBITS 。

.data

.data 节存在于 data 段中，其保存了初始化的全局变量等数据。由于 .data 节保存了程序的变量数据，所以节类型为 SHT_PROGBITS 。

.bss

.bss 节存在于 data 段中，占用空间不超过 4 字节，仅表示这个节本省的空间。 .bss 节保存了未进行初始化的全局数据。程序加载时数据被初始化为 0，在程序执行期间可以进行赋值。由于 .bss 节未保存实际的数据，所以节类型为 SHT_NOBITS 。

.got和.plt

.got 节保存了全局偏移表。 .got 节和 .plt 节一起提供了对导入的共享库函数的访问入口，由动态链接器在运行时进行修改。由于 .got.plt 节与程序执行有关，所以节类型为 SHT_PROGBITS 。

.dynsym

.dynsym 节保存在 text 段中。其保存了从共享库导入的动态符号表。节类型为 SHT_DYNSYM。

.dlnstr

.dynstr 保存了动态链接字符串表，表中存放了一系列字符串，这些字符串代表了符号名称，以空字符作为终止符。

.rel.*

重定位表保存了重定位相关的信息，这些信息描述了如何在链接或运行时，对 ELF 目标文件的某部分或者进程镜像进行补充或修改。由于重定位表保存了重定位相关的数据，所以节类型为 SHT_REL 。

.hash

.hash 节也称为 .gnu.hash ，其保存了一个用于查找符号的散列表。

.systab

.symtab 节是一个 ElfN_Sym 的数组，保存了符号信息。节类型为 SHT_SYMTAB 。

.strtab

.strtab 节保存的是符号字符串表，表中的内容会被 .symtab 的 ElfN_Sym 结构中的 st_name 引用。节类型为 SHT_STRTAB 。

.ctors 节和.dtors 节

.ctors （构造器）节和 .dtors （析构器）节分别保存了指向构造函数和析构函数的函数指针，构造函数是在 main 函数执行之前需要执行的代码；析构函数是在 main 函数之后需要执行的代码。

示例

  1. .text

  2. .symtab

符号表

变量名和函数名都可以叫做符号，专门用来保存符号的节叫做符号表。符号表通常可以分为.dynsym和.symtab，.dynsym中保存的都是在运行时需要用到的一些符号（只有在运行时才会被解析，是运行时动态链接器所需要的符号），而.symtab包含所有的符号，包括.dynsym，但是只是用在链接和调试阶段。

字符串表

类似于符号表，在大多数共享库和动态链接可执行文件中，也存在两个字符串表。即 .dynstr 和 .strtab ，分别对应于 .dynsym 和 symtab 。此外，还有一个 .shstrtab 的节头字符串表，用于保存节头表中用到的字符串，可通过 sh_name 进行索引。
